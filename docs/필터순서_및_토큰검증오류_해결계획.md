# 필터 순서 교정 및 토큰 검증 오류 해결 계획서

이 계획서는 `enabled=false` 설정 시 발생하는 **로그인 후 메뉴 트리 미표출 문제** 및 **브라우저 캐시로 인한 토큰 만료 에러**를 해결하기 위한 구체적인 수정 방향을 제시합니다.

---

## 1. 원인 분석

### ① 로그인 후 메뉴 트리 미표출 원인
* 현재 `ErpTokenValidationFilter`가 JWT 인증을 가로채는 `JwtAuthenticationFilter`보다 **먼저 실행**됩니다.
* 이로 인해, 어드민/저작자 계정으로 **정상 로그인한 사용자**임에도 불구하고 메뉴 트리를 불러오는 `/docs/folders` API 호출 시 토큰이 없어 `ErpTokenValidationFilter`에 의해 403 Forbidden으로 원천 차단당하게 됩니다.
* **해결책**: 필터 실행 순서를 교정하여 **JWT 인증을 먼저 수행**하고, 이미 인증된 어드민/사용자의 요청은 토큰 검증 필터를 **무조건 바이패스(패스)**하도록 수정합니다.

### ② mock index 버튼 클릭 시 "유효하지 않거나 만료된 보안 토큰" 원인
* 브라우저가 `user_manual.jsp`가 반환하는 **리다이렉트 응답(HTTP 302)을 캐싱**하여, 버튼을 두 번째 클릭할 때 JSP를 새로 요청하지 않고 예전에 캐싱해둔 **만료된 토큰 주소로 바로 이동**했기 때문입니다.
* **해결책**: `user_manual.jsp`가 클라이언트에 리다이렉트 응답을 줄 때 브라우저 캐시를 사용하지 않도록 강력한 **Cache-Control 헤더**를 주입합니다.
* 또한, 서명 불일치/시간 만료 등의 세부 실패 사유를 서버 로그에 명확히 기록해 문제 추적성을 확보합니다.

```java
// validateSecureToken 메소드 보강 (IP 대조 로직 탑재)
private boolean validateSecureToken(String tokenStr, String clientIp) {
    try {
        byte[] decodedBytes = Base64.getUrlDecoder().decode(tokenStr);
        String decodedStr = new String(decodedBytes, StandardCharsets.UTF_8);
        
        String[] parts = decodedStr.split(":");
        if (parts.length != 4) {
            log.warn("[ErpTokenFilter] Token split length is not 4. length: {}", parts.length);
            return false;
        }
        
        String userId = parts[0];
        long timestamp = Long.parseLong(parts[1]);
        String ipInToken = parts[2];
        String signature = parts[3];
        
        // 1. 만료 시간 검증 (15초)
        long diff = System.currentTimeMillis() - timestamp;
        if (diff > tokenExpiryMs) {
            log.warn("[ErpTokenFilter] Token expired. Age: {} ms, limit: {} ms", diff, tokenExpiryMs);
            return false;
        }
        
        // 2. IP 검증 (토큰에 기록된 IP와 현재 요청의 IP가 같은지 검사)
        if (!isSameIp(clientIp, ipInToken)) {
            log.warn("[ErpTokenFilter] IP mismatch. Request IP: {}, Token IP: {}", clientIp, ipInToken);
            return false;
        }
        
        // 3. 서명 검증
        String payload = userId + ":" + timestamp + ":" + ipInToken;
        Mac sha256_HMAC = Mac.getInstance("HmacSHA256");
        SecretKeySpec secretKeySpec = new SecretKeySpec(secretKey.getBytes(StandardCharsets.UTF_8), "HmacSHA256");
        sha256_HMAC.init(secretKeySpec);
        byte[] hashBytes = sha256_HMAC.doFinal(payload.getBytes(StandardCharsets.UTF_8));
        String expectedSignature = Base64.getUrlEncoder().withoutPadding().encodeToString(hashBytes);
        
        return expectedSignature.equals(signature);
    } catch (Exception e) {
        log.error("[ErpTokenFilter] Token validation error", e);
        return false;
    }
}

private boolean isSameIp(String ip1, String ip2) {
    if (ip1 == null || ip2 == null) return false;
    if (ip1.equals(ip2)) return true;
    
    // 루프백 계열 예외 처리
    boolean isIp1Loopback = "127.0.0.1".equals(ip1) || "::1".equals(ip1) || "0:0:0:0:0:0:0:1".equals(ip1) || "localhost".equalsIgnoreCase(ip1);
    boolean isIp2Loopback = "127.0.0.1".equals(ip2) || "::1".equals(ip2) || "0:0:0:0:0:0:0:1".equals(ip2) || "localhost".equalsIgnoreCase(ip2);
    return isIp1Loopback && isIp2Loopback;
}
```

## 3. 검증 계획 (보완 완료)

### ① MOCK ERP를 거치지 않은 직접 접속 차단 검증
* **목적**: 토큰 없이 주소창 직접 접속 시 필터에 의해 접근 거부되는지 확인합니다.
* **방법**:
  1. `aman.security.internal-ip.enabled=false`로 설정한 후 백엔드 서버를 구동합니다.
  2. 세션이 만료되도록 크롬 시크릿 창(Incognito)을 켭니다.
  3. 주소창에 `http://localhost:5173/aman/manual/1318`을 직접 입력하여 엔터를 칩니다.
  4. **기대 결과**: 화면에 `403 Forbidden` 과 함께 **"AssetERP 시스템을 정상 경로로 거쳐서 도움말을 열어주시기 바랍니다."** 차단 안내 화면이 표시되는 것을 검증합니다.

### ② 토큰 만료 시간 검증 (15초 초과 시 차단)
* **목적**: 15초 유효 기한을 넘긴 토큰의 접근을 거부하는지 확인합니다.
* **방법**:
  1. `aman-mock`에서 버튼 클릭 후 브라우저가 이동하기 전 URL에 생성된 `token` 파라미터 값(예: `http://localhost:5173/aman/manual/1318?token=...`)을 빠르게 복사합니다.
  2. 복사한 시각으로부터 **15초가 지나기를 대기**합니다.
  3. 15초 후, 크롬 시크릿 창을 띄워 해당 주소로 접속을 시도합니다.
  4. **기대 결과**: `403 Forbidden` 차단 화면이 떠야 하며, 서버 로그(`A-Man.log`)에 `[ErpTokenFilter] Token expired.` 경고 메시지가 기록되는 것을 확인합니다.

### ③ 토큰 URL 복사 후 타 PC(타 IP) 차단 검증
* **목적**: 다른 단말기(다른 IP)에서 토큰 주소를 탈취하여 접속하는 공격을 방어하는지 확인합니다.
* **방법**:
  1. 로컬 PC의 `aman-mock`에서 버튼을 누른 후, 생성된 토큰 URL(`http://192.168.x.x:5173/aman/manual/1318?token=...`)을 복사합니다.
  2. 해당 토큰을 **15초 이내**에 같은 공유기 환경의 스마트폰 브라우저에 입력하여 접속을 시도합니다. (또는 스마트폰에서 mock jsp를 호출한 후 PC로 주소를 복사해 가져옵니다.)
  3. **기대 결과**: 스마트폰의 IP와 토큰 내부의 IP(PC IP)가 서로 불일치하므로 **`403 Forbidden` 차단 화면**이 떠야 하며, 서버 로그에 `[ErpTokenFilter] IP mismatch.` 경고가 남는 것을 검증합니다.
