# A-Man - 화면 보안 및 콘텐츠 유출 방지 강화 방안 (화면보안강화.md)

이 문서는 A-Man 매뉴얼 시스템 내의 노하우 및 업무 흐름 정보가 경쟁사 등으로 유출되는 것을 차단하기 위해, **브라우저 단(Frontend)과 API 통신 단에서 적용할 수 있는 강력한 유출 방지 기법**을 정리한 가이드라인 및 소스코드 수정 계획입니다.

웹 브라우저 환경 특성상 100% 완벽한 유출 차단은 불가능하지만, **"유출에 드는 기술적 비용과 귀찮음을 극대화"**하여 일반 사용자 수준은 물론, IT 기술을 가진 인력의 유출 시도까지 효과적으로 저지하는 것을 목적으로 합니다.

## 2. 보안 기법별 상세 구현 방안

### 2.1 1단계: 브라우저 기본 조작 및 UI 차단

가장 기본적이면서 필수적인 방어선으로, 마우스와 키보드를 통한 정보 수집을 차단합니다.

1. **텍스트 드래그 및 복사 차단 (CSS + JS)**
   * **CSS**: 매뉴얼 콘텐츠가 표시되는 영역에 드래그를 금지합니다.
     ```css
     .manual-content {
       -webkit-user-select: none; /* Safari */
       -ms-user-select: none;     /* IE 10+ */
       user-select: none;         /* 표준 */
     }
     ```
   * **JS**: `copy`, `selectstart`, `contextmenu` 이벤트를 가로채서 원천 차단합니다.
     ```javascript
     document.addEventListener('contextmenu', e => e.preventDefault()); // 우클릭 방지
     document.addEventListener('selectstart', e => e.preventDefault()); // 드래그 시작 방지
     document.addEventListener('copy', e => {
       e.preventDefault();
       alert('본 시스템의 콘텐츠는 복사할 수 없습니다.');
     });
     ```

2. **핵심 단축키 차단**
   * 정보 탈취에 흔히 쓰이는 키 조합을 브라우저 수준에서 차단합니다.
   * `F12`, `Ctrl + Shift + I` (개발자 도구)
   * `Ctrl + U` (페이지 소스 보기)
   * `Ctrl + S` (페이지 저장)
   * `Ctrl + P` (인쇄 기능)
     ```javascript
     document.addEventListener('keydown', function(e) {
       if (e.keyCode === 123) { e.preventDefault(); }
       if (e.ctrlKey && e.shiftKey && (e.keyCode === 73 || e.keyCode === 67 || e.keyCode === 74)) { e.preventDefault(); }
       if (e.ctrlKey && (e.keyCode === 83 || e.keyCode === 80 || e.keyCode === 85)) { e.preventDefault(); }
     });
     ```

3. **인쇄(Print) 레이아웃 무력화 (CSS @media print)**
   * 사용자가 브라우저 인쇄 기능을 통해 PDF 파일로 전체 매뉴얼을 저장하려는 시도를 차단합니다.
   * 인쇄 시점에 화면 전체를 보이지 않게 감추거나, 보안 경고 문구만 노출합니다.
     ```css
     @media print {
       body {
         display: none !important; /* 인쇄 시 화면을 아예 숨김 */
       }
     }
     ```

### 2.2 2단계: 개발자 도구(F12) 무력화 및 감시

IT 지식이 있는 사용자는 F12를 열어 CSS를 강제로 해제하거나 HTML DOM 트리에서 직접 텍스트를 긁어갑니다. 이를 방지하는 고도화된 스크립트입니다.

1. **무한 디버거(Anti-Debugging) 기법**
   * 개발자 도구가 활성화되면 브라우저가 강제로 `debugger;` 코드에서 일시정지되도록 만듭니다.
   * 개발자 도구를 켜는 즉시 화면이 얼어버리거나(Freeze), 디버거 탭이 무한 루프에 빠져 정상적인 DOM 탐색이 불가능해집니다.
     ```javascript
     setInterval(function() {
       (function() {
         try {
           (function a(i) {
             if (("" + i / i).length !== 1 || i % 20 === 0) {
               (function() {}).constructor("debugger")();
             } else {
               debugger;
             }
             a(++i);
           })(0);
         } catch (e) {}
       })();
     }, 1000);
     ```

2. **윈도우 크기 변화 감지 (DevTools 도킹 감지)**
   * 개발자 도구가 브라우저 하단이나 우측에 열릴 때, 브라우저의 내부 창 크기(`window.innerWidth`, `window.innerHeight`)가 급격히 줄어드는 원리를 이용해 감지합니다.
   * 감지 시 화면을 즉시 화이트아웃 처리하고 세션을 끊는 조치를 취할 수 있습니다.

### 2.3 3단계: 스크래핑 및 네트워크 크롤러 방어 (고급)

Python `BeautifulSoup`, `Selenium` 등을 이용해 API 엔드포인트를 직접 호출하여 매뉴얼 1,000개를 한 번에 긁어가는 시나리오를 막는 최첨단 방어법입니다.

1. **API 응답 데이터 암호화 (Payload Encryption)**
   * A-Man 서버가 매뉴얼 콘텐츠(Markdown 텍스트 등)를 반환할 때, 일반 JSON이 아닌 **AES-256 알고리즘으로 암호화된 암호문(Ciphertext)**만 보냅니다.
   * **네트워크 탭(F12 > Network) 보안**: 해커가 API 호출을 직접 덤프하더라도 알아볼 수 없는 깨진 문자열만 보입니다.
   * **복호화**: 프론트엔드 JavaScript 단에서 실시간으로 대칭키를 이용하여 복호화한 후 화면(React State)에 바인딩합니다. 이 대칭키는 빌드 단계에서 난독화 코드 내에 숨겨집니다.
   * **API Payload 예시**:
     ```json
     // 서버 응답 (Before) -> 평문
     { "content": "## 자산 관리 업무 흐름도\n1. 자산 등록..." }

     // 서버 응답 (After) -> 암호화
     { "data": "U2FsdGVkX19zS0Y4Z2h...[생략]...vZmhzYVR5Tmc9PQ==" }
     ```

2. **폰트 난독화 (Font Obfuscation)**
   * 매뉴얼 글자의 유니코드를 매칭 테이블에 따라 뒤섞은 특수 폰트 파일(.woff)을 사용합니다.
   * **동작 원리**: 
     * 화면상에는 정상적인 한글 `'자산 등록'`으로 보이지만, 실제로 DOM 소스에 배치된 문자는 `'aB3# eD'` 형태입니다.
     * 크롤러가 HTML을 긁어가거나, 사용자가 드래그해서 메모장에 붙여넣으면 무의미한 깨진 문자열만 얻게 됩니다.
     * 오직 전용 폰트가 설치된 브라우저 렌더러에서만 올바른 글자로 렌더링됩니다.
   * *주로 웹소설, 유료 웹툰, 증권 리포트 플랫폼에서 사용하는 최고 수준의 텍스트 복사 차단 기법입니다.*

3. **CSS 가상 요소(`::before`, `::after`) 결합**
   * 중요한 키워드(예: 담당자명, 결제 라인, 시스템 특수 파라미터)를 HTML 본문 텍스트에 포함하지 않고, 난독화된 CSS의 `content` 속성으로 동적 삽입합니다.
   * 스크래핑 엔진이 기본 HTML 파서만 사용할 경우 핵심 정보가 누락됩니다.

### 2.4 4단계: 동적 워터마크 (Watermark) 도입

화면을 폰으로 직접 사진 촬영하거나 화면 캡처 프로그램(스니핑 툴)을 사용하여 이미지로 유출하는 것은 기술적으로 완전 차단이 불가합니다. 이 경우 **추적 및 심리적 방어**가 가장 효과적입니다.

1. **동적 워터마크 오버레이**
   * 화면 전체에 격자 무늬로 **"현재 접속한 사용자 사원번호 + 로그인 IP + 현재 시각"**을 흐리게(투명도 3%~7%) 깔아둡니다.
   * 사진 촬영이나 캡처 이미지 뒤에 해당 사원의 정보가 선명히 박히게 되므로, **"유출 시 본인이 즉시 특정된다"**는 강력한 심리적 억제력이 생깁니다.

2. **MutationObserver를 통한 워터마크 강제 보호**
   * 똑똑한 사용자가 개발자 도구(F12)로 워터마크를 담당하는 `<div>` 태그를 `display: none`으로 설정하거나 DOM에서 삭제하는 행위를 실시간 감시합니다.
   * **JS 감시 로직**:
     ```javascript
     const target = document.getElementById('security-watermark');
     const observer = new MutationObserver(mutations => {
       mutations.forEach(mutation => {
         alert('보안 요소를 훼손하였습니다. 접근이 제한됩니다.');
         window.location.reload();
       });
     });
     observer.observe(target, { attributes: true, childList: true, characterData: true });
     ```

## 3. 1단계 브라우저 제약 - 상세 구현 계획

A-Man의 두 가지 진입 경로인 **React 뷰어(/docs)**와 **Java 뷰어(/manual)** 모두에 아래 소스 수정을 적용합니다.

### 3.1 React 프론트엔드 영역 수정 (/docs)

React는 `/docs/page/:page_id` 진입 시 `MarkdownViewer.tsx` 컴포넌트가 활성화되므로, 관련 파일 3곳을 수정합니다.

#### 1) [NEW] `frontend/src/utils/useSecurity.ts`
컴포넌트 단위에서 우클릭 방지, 복사 방지, 단축키 차단 이벤트를 리스닝하는 React 커스텀 훅을 생성합니다.

```typescript
import { useEffect } from 'react'

export function useSecurity(enabled: boolean = true) {
  useEffect(() => {
    if (!enabled) return

    // 우클릭 및 텍스트 드래그/선택 시작 방지
    const handleContextMenu = (e: MouseEvent) => e.preventDefault()
    const handleSelectStart = (e: Event) => e.preventDefault()
    const handleCopy = (e: ClipboardEvent) => {
      e.preventDefault()
      alert('보안 정책상 매뉴얼 텍스트를 복사할 수 없습니다.')
    }

    // 단축키 제한 (F12, Ctrl+Shift+I/C/J, Ctrl+S/P/U)
    const handleKeyDown = (e: KeyboardEvent) => {
      // F12
      if (e.key === 'F12' || e.keyCode === 123) {
        e.preventDefault()
        return
      }

      // Ctrl + Shift + I/C/J (개발자도구 관련)
      if (e.ctrlKey && e.shiftKey && (e.key === 'I' || e.key === 'C' || e.key === 'J' || e.keyCode === 73 || e.keyCode === 67 || e.keyCode === 74)) {
        e.preventDefault()
        return
      }

      // Ctrl + S (저장), Ctrl + P (인쇄), Ctrl + U (소스보기)
      if (e.ctrlKey && (e.key === 's' || e.key === 'p' || e.key === 'u' || e.key === 'S' || e.key === 'P' || e.key === 'U' || e.keyCode === 83 || e.keyCode === 80 || e.keyCode === 85)) {
        e.preventDefault()
        return
      }
    }

    document.addEventListener('contextmenu', handleContextMenu)
    document.addEventListener('selectstart', handleSelectStart)
    document.addEventListener('copy', handleCopy)
    document.addEventListener('keydown', handleKeyDown)

    return () => {
      document.removeEventListener('contextmenu', handleContextMenu)
      document.removeEventListener('selectstart', handleSelectStart)
      document.removeEventListener('copy', handleCopy)
      document.removeEventListener('keydown', handleKeyDown)
    }
  }, [enabled])
}
```

  ### 1. 보안 차단 항목 및 테스트 방법

   차단 항목		  | 사용자의 시도 (테스트 액션)			| 기대 결과 (차단 동작)
  ------------------------|---------------------------------------------|----------------------------------------------
   마우스 우클릭 방지     | 매뉴얼 화면 아무 곳에나 마우스 오른쪽 클릭  | 컨텍스트 메뉴(복사, 소스 보기 등)가 아예
                          |                                             | 나타나지 않음
   드래그 금지            | 텍스트를 마우스 드래그로 선택 시도          | 텍스트가 블록 지정(선택)되지 않음
   복사 차단		  | 강제로 영역을 지정하거나 복사(Ctrl + C)     | '보안 정책상 매뉴얼 텍스트를 복사할 수

## 핸드쉐이크 암호 기능

### 방법 ①: 무상태(Stateless) 암호화 키 유도 방식 (가장 추천)

  서버나 DB에 키 정보를 아무것도 저장하지 않고, 요청이 들어올 때마다 서버가 가진 고유의 비밀값(Salt)과 요청자의 정보를
  조합하여 즉석에서 키를 계산하는 방식입니다.
  즉 curl , request와 같이 단순하게 url을 호출해서 manual을 scrapping 해 가는 것을 막는다.

  • 원리:
      • 키 생성 규칙: 임시 키 = SHA-256( 서버 고유 Salt + 요청자 IP + 현재 시간 블록(예: 10분 단위) )
  • 동작 흐름:
      1. 프론트엔드가 /api/security/handshake를 호출하면, 서버는 요청자의 IP와 현재 시간 블록을 사용해 임시 키를
      계산해서 응답합니다.
      2. 프론트엔드가 특정 매뉴얼 데이터를 요청하면, 서버는 똑같이 해당 요청자의 IP와 현재 시간 블록으로 즉석에서 키를
      계산하여 데이터를 암호화한 후 보냅니다.
      3. 프론트엔드는 가지고 있던 키로 데이터를 복호화합니다.
  • 장점:
      • 저장 공간이 전혀 필요 없음: 서버 메모리도 사용하지 않고 DB도 쓰지 않아 오버헤드가 0입니다.
      • 보안성: 키가 IP에 종속되어 있어 다른 컴퓨터(IP)에서 키를 탈취해 가도 작동하지 않으며, 10분이 지나면 키가
      자동으로 만료됩니다.
