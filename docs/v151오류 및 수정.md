## 1. 목표 및 배경

로그 분석 결과 두 가지 주요 오류/경고 패턴이 식별되었습니다.

### 오류 1: `EntityNotFoundException: Unable to find kr.co.kfs.aman.model.Folder with id 124`
* **로그 위치**: 7~111행, 139~243행, 244~348행.
* **원인**: 사용자가 폴더를 삭제할 때 (`FolderController.deleteFolder` 호출 시) 해당 폴더와 연계된 사용자의 최근 작업 이력(`work_stack` 테이블) 레코드를 정리하지 않습니다. 이후 사용자가 최근 작업 목록을 조회(`GET /admin/work-stack`)하는 과정에서, 삭제된 폴더 ID 124에 대한 정보(이름, 번호 등)를 지연 로딩(Lazy Loading)으로 조회하려고 시도하다가 `EntityNotFoundException`이 발생합니다.
* **해결 방법**: 폴더가 삭제될 때 해당 폴더와 하위 폴더들에 대한 `WorkStack` 이력 데이터도 함께 트랜잭션 내에서 삭제해 데이터 무결성을 유지합니다.

### 오류 2: `MethodArgumentTypeMismatchException: Failed to convert value of type 'java.lang.String' to required type 'java.lang.Long'`
* **로그 위치**: 3행.
* **원인**: `ContentController`에서 정의된 `@GetMapping("/{page_id}")` 매핑 패턴이 너무 범용적이어서 `/content/image` 또는 `/content/export` 등 다른 정적 엔드포인트 요청까지 낚아챕니다. 이 과정에서 경로 파라미터인 `page_id`에 `"image"`나 `"export"` 문자열이 들어가고, 이를 `Long` 타입으로 변환하려고 시도하다 실패해 예외가 발생합니다.
* **해결 방법**: `ContentController` 내 dynamic path 파라미터가 숫자만 인식할 수 있도록 정규식 제약(`{page_id:\\d+}`)을 추가합니다.

> [!IMPORTANT]
> 폴더 삭제가 발생하면 해당 폴더 및 모든 하위 폴더에 연결된 `WorkStack` 사용자 이력이 즉시 영구 삭제(Hard Delete)됩니다. 따라서 삭제된 카테고리는 사용자의 최근 이력 목록에서 노출되지 않게 되며, 이는 무결성을 위한 의도된 동작입니다.

## 3. 상세 수정 내용

### 3.1 [WorkStackRepository.java](file:///home/kdy987/work/aman/backend/src/main/java/kr/co/kfs/aman/repository/WorkStackRepository.java) 수정
특정 폴더 ID와 연계된 작업 이력을 일괄 삭제하는 쿼리 메서드를 추가합니다.

```java
package kr.co.kfs.aman.repository;

import kr.co.kfs.aman.model.WorkStack;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Modifying;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;
import java.util.Optional;

@Repository
public interface WorkStackRepository extends JpaRepository<WorkStack, Long> {
    List<WorkStack> findByUserIdOrderByCreatedAtDesc(Long userId);
    Optional<WorkStack> findByUserIdAndFolderId(Long userId, Long folderId);

    @Modifying
    @Query("DELETE FROM WorkStack w WHERE w.folder.id = :folderId")
    void deleteByFolderId(@Param("folderId") Long folderId);
}
```

### 3.2 [FolderController.java](file:///home/kdy987/work/aman/backend/src/main/java/kr/co/kfs/aman/controller/FolderController.java) 수정
`WorkStackRepository`를 주입받아 폴더 재귀 삭제 시 관련 작업 이력(`WorkStack`)을 정리합니다.

```java
// Fields and constructor update
private final FolderRepository folderRepository;
private final PageRepository pageRepository;
private final WorkStackRepository workStackRepository;

public FolderController(FolderRepository folderRepository, PageRepository pageRepository, WorkStackRepository workStackRepository) {
    this.folderRepository = folderRepository;
    this.pageRepository = pageRepository;
    this.workStackRepository = workStackRepository;
}

// Modify deleteFolderRecursive to clean up work stack
private void deleteFolderRecursive(Folder folder) {
    // 1. 해당 폴더 하위에 연결된 모든 페이지(manual 내용) 삭제
    List<Page> pages = pageRepository.findByFolderIdOrderBySortOrderAsc(folder.getId());
    if (pages != null && !pages.isEmpty()) {
        pageRepository.deleteAll(pages);
    }
    
    // 1.5. 작업 이력(WorkStack) 삭제
    workStackRepository.deleteByFolderId(folder.getId());
    
    // 2. 자식 폴더들 재귀 삭제
    for (Folder child : folder.getChildren()) {
        deleteFolderRecursive(child);
    }
}
```
